🤔 O Problema

Por que precisamos de Service Discovery?

  • Sistemas antigos: Aplicações monolíticas em um único servidor com endereço fixo
  • Sistemas modernos: Centenas de microsserviços distribuídos em múltiplos servidores
  • Desafio: Serviços constantemente iniciam, param, escalam e mudam de endereço
  • Pergunta: Como um serviço encontra e se comunica com outro de forma dinâmica?

🎵 Exemplo: Spotify

• Serviço de Música precisa falar com Serviço de Pagamento

• Serviço de Recomendação precisa dos dados do Serviço de Usuários

• Problema: Esses serviços podem estar em qualquer máquina e mudar a qualquer momento!

💡 O que é Service Discovery?

Definição

  • Mecanismo que permite serviços encontrarem e se comunicarem automaticamente
  • Funciona como uma "lista telefônica dinâmica" para microsserviços
  • Mantém registro atualizado de onde cada serviço está rodando
  • Abstrai a complexidade de localização em ambientes cloud dinâmicos

📋 Service Registry

O Catálogo Central

  • Banco de dados centralizado que armazena informações de todos os serviços
  • Registra: Nome do serviço, endereço IP, porta, estado de saúde, metadados
  • Atualiza: Informações em tempo real conforme serviços entram/saem
  • Consulta: Permite que serviços busquem informações de outros serviços

⚙️ Como Funciona?

Fluxo de Operação

  • 1. Registro: Quando um serviço inicia, ele se registra no Service Registry
  • 2. Heartbeat: Serviço envia "sinais de vida" periódicos (ex: a cada 30s)
  • 3. Consulta: Quando precisa falar com outro serviço, consulta o Registry
  • 4. Comunicação: Usa as informações obtidas para estabelecer conexão
  • 5. Desregistro: Ao parar, serviço remove-se ou Registry detecta ausência

🔀 Tipos de Service Discovery

👤 Client-Side

  • Cliente consulta o Registry diretamente
  • Cliente escolhe qual instância usar
  • Conexão direta ao serviço
  • Exemplo: Netflix Eureka
✅ Vantagem: Menor latência
⚠️ Desafio: Cliente mais complexo

🖥️ Server-Side

  • Cliente envia requisição ao Load Balancer
  • Load Balancer consulta o Registry
  • Load Balancer roteia a requisição
  • Exemplo: AWS ELB, Kubernetes
✅ Vantagem: Cliente mais simples
⚠️ Desafio: Hop adicional (latência)

🌍 Exemplos no Mundo Real

🎬 Netflix

Escala: 700+ microsserviços

Ferramenta: Eureka (desenvolvido pela própria Netflix)

Uso: Permite que serviços de streaming, recomendação, billing e outros se encontrem dinamicamente em centenas de servidores

🚗 Uber

Escala: 2000+ microsserviços

Ferramentas: Consul + Envoy

Uso: Coordena serviços de localização, pagamento, notificações, matching motorista-passageiro em tempo real

☁️ AWS / Kubernetes

AWS: Cloud Map + ELB para service discovery nativo

Kubernetes: DNS interno + Service objects para descoberta automática

Uso: Infraestrutura gerenciada para milhares de empresas globalmente

⚖️ Vantagens e Desafios

✅ Vantagens

  • Elimina configuração manual de endereços
  • Escala automaticamente com a aplicação
  • Tolerância a falhas com health checks
  • Deploy sem downtime (rolling updates)
  • Balanceamento de carga inteligente

⚠️ Desafios

  • Registry pode ser ponto único de falha
  • Consistência eventual em updates
  • Latência adicional nas consultas
  • Complexidade de configuração inicial
  • Necessidade de monitoramento constante
